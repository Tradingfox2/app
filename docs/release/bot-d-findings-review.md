## Artwork

All twelve files on `origin/release/bot-b-visual` under `docs/release/bot-b/art/` were read. Each is a short SVG, `viewBox="0 0 64 64"`, `fill="none"`, stroke `#F2F3F4` at 2.25. There is no `href`, no embedded image, no Inkscape/Figma/license comment, and no remote paint server beyond the SVG namespace. The monogram is two rounded rects and a horizontal bar. The equipment glyphs are the same kind of diagram. The body glyphs are stick figures with a featureless head circle and no face. They are not the Expo template logo, not the staff chevron in `staff/auth.tsx`, and not an Ionicons path (those ship as a font). They are original drawings for this proposal and are safe to copy into a member module. Chartreuse is absent from the files, which matches the “action color stays on the control” rule.

Do not treat them as a license to draw a person. Bot B already says not to ship `portrait-coach.svg`. That constraint holds.

## Staff menu, historical Playwright failures

Reported earlier as mobile-only timeouts: Menu did not reveal `admin-tab-users` / `admin-tab-audit`, and the moderator-suspend and support-queue-filter tests failed on the mobile project while passing on desktop and when re-run alone (`docs/athlete-review-bot-d.md`, `docs/athlete-redesign-report.md`).

On current `9604bac`, Chromium mobile **390×844**, `isMobile` and `hasTouch`:

- One mouse click and one `tap()` each opened the drawer. The control’s name changed from Menu to Close menu. The users tab was in the layout (`offsetParent` set).
- `npx playwright test e2e/admin.spec.ts --project=mobile` for “moderator resolves a report and must give a reason to suspend”, “audit tab shows who did what”, and “support queue can hide assigned tickets”, **twice**: **6 passed**, about 1.3–1.9s each. No retry inside the reporter.

Classification: **flaky**. The drawer opens on this commit. The failures were not reproduced as a stuck menu, so this is not a deterministic navigation bug. It is also not “the machine cannot click.” The helper in `frontend/e2e/staff-nav.ts` clicks Menu, waits 8s, and if the tab is still hidden clicks again whenever `aria-expanded` is not `"true"`. That attribute is never set (D-03), including while the drawer is open. A slow first paint therefore gets a second click that closes the drawer, and the test times out. An immediate re-run, with a warm bundle, passes. Fix the helper when D-03 is fixed. Do not change staff layout to chase the flake.
